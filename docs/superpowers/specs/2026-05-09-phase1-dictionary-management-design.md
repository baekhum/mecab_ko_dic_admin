## 1. 목표

MeCab 시스템 사전, 사용자 사전, 복합명사 사전, 동의어 및 불용어를 Django Admin과 관리 명령에서 일관되게 관리한다. Phase 1의 완료 기준은 모델이 존재하는 것만이 아니라 데이터 무결성, 반복 가능한 CSV import, 관리 화면의 검색성, 오류 발생 시 안전한 롤백과 자동화된 검증이 모두 확보되는 것이다.

## 2. 기술 기준

- Python `>=3.12,<3.13`
- Django `>=5.2,<5.3` (5.2 LTS)
- PostgreSQL 17
- uv
- Django test runner 및 Ruff

모든 Phase 1 작업은 `docs/superpowers/plans/2026-08-30-python-django-version-alignment.md`의 런타임 정렬을 선행 조건으로 한다. 실제 환경이 위 범위를 충족하지 않으면 애플리케이션 작업을 시작하지 않고 버전 정렬 계획을 먼저 완료한다.

## 3. 현재 구현 기준선

다음 요소는 저장소에 이미 존재한다. 구현 계획은 이를 처음부터 다시 만들지 않고, 마이그레이션 상태와 테스트로 기준선을 검증한 뒤 미충족 요구만 보완한다.

- `Mecab_Ko_Dic`의 `origin_type`, `is_active` 필드
- `SynonymGroup`, `SynonymWord`, `Stopword` 모델과 관련 마이그레이션
- `(표층형, 품사_태그)` 유일성 제약
- `import_mecab_csv` 및 `export_mecab_csv` 관리 명령
- 사전 검색·필터와 동의어 인라인을 제공하는 Django Admin
- 모델 및 import 명령 테스트

기준선은 완료 선언이 아니다. 구현 계획의 검증 명령이 실패하거나 아래 계약을 충족하지 못하면 해당 항목을 보완 대상으로 취급한다.

## 4. 데이터 모델과 무결성 계약

### 4.1 통합 MeCab 사전 모델 (`Mecab_Ko_Dic`)

- `origin_type`: `SYSTEM`, `USER`, `COMPOUND` 중 하나이며 출처를 나타낸다.
- `is_active`: 후속 사전 빌드에 포함할지를 나타내는 운영 상태다. Phase 1은 이 값을 저장하고 재import에서 보존하며, 실제 빌드 적용은 후속 단계에서 담당한다.
- `표층형`, `품사_태그`, `읽기`는 검색 대상이며 DB 인덱스를 갖는다.
- `origin_type`, `is_active`는 Admin 필터 대상이며 DB 인덱스를 갖는다.
- `(표층형, 품사_태그)`는 출처와 무관한 전역 식별 키다. 동일 키를 다시 import하면 새 행을 추가하지 않고 기존 행을 갱신한다.
- 재import는 CSV에서 제공되는 사전 속성과 `origin_type`을 갱신하되 운영자가 설정한 `is_active` 값은 보존한다.
- `품사_태그`는 지원 목록의 단일 태그 또는 `+`로 연결된 복합 태그여야 한다.
- `종성_유무`는 `T`, `F`, `*` 중 하나여야 한다.

### 4.2 검색 확장 사전

- `SynonymGroup.name`은 전역에서 유일하다.
- `SynonymWord`는 같은 그룹 안에서 같은 단어를 중복 저장할 수 없다.
- `SynonymGroup`을 삭제하면 소속 `SynonymWord`도 함께 삭제한다.
- `Stopword.word`는 전역에서 유일하다.

위 규칙은 DB 제약과 자동화된 테스트로 함께 보호한다.

## 5. CSV import 계약

### 5.1 입력 형식

- 헤더가 없는 MeCab 12열 CSV를 입력으로 받는다.
- 열 순서는 `표층형`, LID, RID, cost, `품사_태그`, `의미_부류`, `종성_유무`, `읽기`, `타입`, `첫번째_품사`, `마지막_품사`, `표현`이다.
- 기본 인코딩은 UTF-8이며 `--encoding`으로 다른 인코딩을 지정할 수 있다.
- `--type`은 `SYSTEM`, `USER`, `COMPOUND`만 허용한다.
- `--batch_size`는 양의 정수여야 한다.

### 5.2 중복과 업데이트

- 파일 내부에서 `(표층형, 품사_태그)`가 중복되면 마지막 행을 적용한다.
- DB에 같은 키가 있으면 UPSERT한다.
- UPSERT는 사전 속성과 `origin_type`을 갱신하고 기존 `is_active`는 유지한다.

### 5.3 오류와 트랜잭션

- 열 개수, 품사 태그, 종성 값, 필수 문자열 및 옵션 값이 잘못된 행은 행 번호와 원인을 보고한다.
- 하나라도 잘못된 행이 있으면 명령은 실패 상태로 종료하고 해당 파일에서 수행한 변경 전체를 롤백한다.
- 파일 부재와 디코딩 오류는 `CommandError`로 변환해 조치 가능한 메시지를 제공한다.
- 성공 시 처리, 적용(생성 또는 갱신), 오류 건수를 요약한다.

## 6. Django Admin 계약

- MeCab 목록은 `origin_type`, `품사_태그`, `is_active`로 필터링할 수 있다.
- `표층형`, `읽기`, `품사_태그`, `의미_부류`를 검색할 수 있다.
- 시스템 사전은 조회할 수 있지만 Admin에서 수정하거나 삭제할 수 없다.
- 사용자 및 복합명사 사전은 권한 범위에서 편집할 수 있다.
- `SynonymWord`는 `SynonymGroup` 화면에서 인라인으로 관리한다.
- 불용어는 목록 검색과 추가·삭제를 지원한다.

## 7. 범위 제외

- Elasticsearch 또는 Solr 인덱싱 연동
- Docker 컨테이너 내부의 MeCab 사전 자동 빌드
- Phase 1 모델을 사용하는 별도 사용자용 웹 UI 또는 API

이 항목들은 후속 단계에서 다룬다. Phase 1에서는 향후 연동에 필요한 데이터 계약과 export 가능성만 보장한다.

## 8. 완료 조건

Phase 1은 다음 조건을 모두 충족할 때 완료된다.

1. 런타임이 Python 3.12.x와 Django 5.2.x로 고정된다.
2. 모델과 마이그레이션이 일치하고 미생성 마이그레이션이 없다.
3. 데이터 무결성 및 CSV 계약의 정상·오류 경로가 자동 테스트로 검증된다.
4. Admin 필터, 검색, 읽기 전용 정책과 동의어 인라인이 테스트된다.
5. Django test runner 전체 테스트, Ruff 및 Django system check가 통과한다.
6. 실제와 같은 소형 MeCab fixture를 두 번 import해 행 수가 증가하지 않고 갱신 정책이 유지됨을 검증한다.
